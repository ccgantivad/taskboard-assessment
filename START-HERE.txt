1. CHOOSE THE WORKING ENVIRONMENT

Assumption: Windows x64 with VS Code. Use native Windows .NET/Node and Docker
Desktop with its WSL2 Linux backend. If your current development environment
already works in WSL2, stay there, keep the repository under /home/<you>/...,
and open VS Code from WSL with code . . Avoid mixing Windows and Linux toolchains.
SQL Server's Linux image requires a supported x86-64 host; ARM emulation is not
a supported SQL Server setup. A native SQL Server instance can replace Docker.

Install/verify these prerequisites from their official sites:
- Git; VS Code; .NET 10 SDK (not just runtime).
- Node.js 24 LTS >=24.15.0; npm is bundled with Node.
- Docker Desktop with Linux containers and WSL2 backend.
- Official Codex extension (OpenAI), C# Dev Kit and Angular Language Service.

Run the read-only audit in PowerShell:
  ./scripts/preflight.ps1
If PowerShell blocks the local script, inspect it and paste its read-only
commands into the terminal. Do not weaken machine-wide execution policy.

3. START SQL SERVER

Copy the example and set a unique strong local password in the new file:
  Copy-Item .env.example .env
  code .env

Do not commit .env or paste the password into prompts. If using a simple
unquoted .env value, avoid interpolation characters such as $ and #.

Start the container and wait until its status is healthy:
  docker compose up -d --wait
  docker compose ps

The container has a persistent named volume and a read-only /scripts mount.
Run the creation script, then the demonstration queries. These PowerShell
commands expand the password only inside the container, not in your history:

The outer single quotes preserve the literal shell variable in Windows
PowerShell 5.1 and PowerShell 7. The shell assignment deliberately contains no
embedded quotation marks; Bash does not split values in an assignment.

  docker compose exec -T sqlserver bash -c 'SQLCMDPASSWORD=$MSSQL_SA_PASSWORD /opt/mssql-tools18/bin/sqlcmd -S localhost -U sa -C -b -i /scripts/001_create.sql'

  docker compose exec -T sqlserver bash -c 'SQLCMDPASSWORD=$MSSQL_SA_PASSWORD /opt/mssql-tools18/bin/sqlcmd -S localhost -U sa -C -b -i /scripts/002_seed.sql'

  docker compose exec -T sqlserver bash -c 'SQLCMDPASSWORD=$MSSQL_SA_PASSWORD /opt/mssql-tools18/bin/sqlcmd -S localhost -U sa -C -b -i /scripts/003_json_examples.sql'

  docker compose exec -T sqlserver bash -c 'SQLCMDPASSWORD=$MSSQL_SA_PASSWORD /opt/mssql-tools18/bin/sqlcmd -S localhost -U sa -C -b -i /scripts/004_constraint_checks.sql'

Use the actual filenames included in database/ if they differ. Keep the schema
script canonical and map EF Core to it; do not call EnsureCreated or silently
introduce a second competing setup method. In the final README, state that this
is script-driven schema setup. A normal docker compose down preserves data;
docker compose down -v erases the database volume, so use it only intentionally.

4. SCAFFOLD THE BACKEND (MANUAL, AFTER REVIEW)

Run from repository root after confirming .NET 10 is selected:
  dotnet --version
  dotnet new globaljson --sdk-version <exact-installed-10.x-sdk> --roll-forward latestPatch
Replace the angle-bracket placeholder with the installed SDK version.

  dotnet new sln -n TaskBoard --format sln
  dotnet new webapi --use-controllers -f net10.0 -n TaskBoard.Api -o backend/TaskBoard.Api
  dotnet sln TaskBoard.sln add backend/TaskBoard.Api/TaskBoard.Api.csproj
  dotnet add backend/TaskBoard.Api package Microsoft.EntityFrameworkCore.SqlServer --version "10.*"
  dotnet new xunit -f net10.0 -n TaskBoard.Tests -o tests/TaskBoard.Tests
  dotnet sln TaskBoard.sln add tests/TaskBoard.Tests/TaskBoard.Tests.csproj
  dotnet add tests/TaskBoard.Tests reference backend/TaskBoard.Api/TaskBoard.Api.csproj

The package command selects a current 10.x patch but may retain a floating
version in the project. Run dotnet list backend/TaskBoard.Api package, then
replace 10.* in the .csproj with that resolved exact 10.x.y version and restore.
Commit the concrete version. Do not confuse the SDK version with the runtime
version. Use one backend project with Controllers,
Services, Repositories, Data, Models and DTOs. Name the C# task entity TaskItem.

Use .NET user-secrets for ConnectionStrings:DefaultConnection. Initialize it:
  dotnet user-secrets init --project backend/TaskBoard.Api
Then use the C# Dev Kit/IDE user-secrets editor or a local secure input workflow
to set the connection string, without putting a real password in this guide.
Local connection string shape:
  Server=localhost,1433;Database=TaskBoard;User Id=sa;Password=<local password>;Encrypt=True;TrustServerCertificate=True
TrustServerCertificate=True and sqlcmd -C are for this local development setup.
Use validated certificates and an appropriate application login in production.
